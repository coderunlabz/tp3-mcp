## Arquivo de conteúdo

Um arquivo é markdown com frontmatter. Outro aluno troca a pasta inteira.

```yaml
---
tema: string
fonte: string
autor: string
---
```

`tema` é o assunto curto usado para agrupar dúvida. `fonte` é a origem citável (URL ou referência). `autor` é quem escreveu o material. Os três são obrigatórios. Sem eles o arquivo não entra no acervo.

Pastas, e só elas, separam o tipo:

- `conteudo/slides/NN-titulo.md` — `NN` é o número do slide, com dois dígitos.
- `conteudo/manual/` — passos de instalação, na ordem do nome do arquivo.
- `conteudo/referencias/` — leituras extras.
- `conteudo/sobre.md` — um arquivo só, com os três campos acima mais `titulo` e `versao`. É a ficha que `sobre_este_acervo` lê.

Bloco opcional, no fim do arquivo, para `checar_entendimento`. Some de toda leitura que o modelo recebe (resource, trecho, prompt):

```markdown
:::checagem
pergunta: texto da pergunta
resposta: texto esperado
:::
```

Comparação da resposta do aluno: o servidor normaliza caixa e espaços e exige igualdade. Não há modelo dentro do servidor.

## Prompts

O nome no protocolo não leva barra. A barra é o jeito de falar do atalho. Se o cliente não lista prompts, a pessoa cola o mesmo texto. Não existe tool extra por atalho: o texto manda o modelo usar as cinco tools abaixo.

Cada prompt devolve uma mensagem de usuário com o texto abaixo.

### comece-aqui

Sem argumento. Descrição: ponto de entrada; explica o que há no acervo e lista os outros atalhos.

Texto:

> Use as tools deste servidor e nada de fora dele. Chame `sobre_este_acervo` e conte, em linguagem leiga, o que este acervo é, de quem é e o que está carregado. Depois liste os atalhos: explica-como-se-eu-tivesse-5-anos, mostra-o-slide, me-guia-na-instalacao, prepara-minha-prova, onde-posso-ler-mais. Diga que dúvida da plateia entra por `registrar_duvida` e que `ver_duvidas_da_sala` é só de quem está apresentando.

### explica-como-se-eu-tivesse-5-anos

Argumento `assunto` (texto, opcional). Descrição: o assunto sem jargão, com uma analogia tirada do acervo.

Texto:

> Explique {assunto} como para uma criança de 5 anos, com uma analogia. Chame `consultar_acervo` com esse assunto. Use só o trecho devolvido. Se a tool disser que não consta, repita isso e não complete com conhecimento seu. Se assunto vier vazio, pergunte qual tema do acervo a pessoa quer.

### mostra-o-slide

Argumento `numero` (número, obrigatório). Descrição: conta o slide N em voz de apresentação.

Texto:

> Abra o resource do slide {numero} e apresente o conteúdo em voz alta, como quem fala para a turma, sem ler o frontmatter. Se o resource não existir, diga o erro da tool e pergunte outro número.

### me-guia-na-instalacao

Argumento `passo` (número, opcional; ausente significa 1). Descrição: um passo do manual por vez.

Texto:

> Leia o resource do manual no passo {passo}. Mostre só esse passo, com arquivo e fonte. Termine perguntando se deu certo. Não antecipe o passo seguinte.

### prepara-minha-prova

Argumento `foco` (texto, opcional). Descrição: estudo a partir do acervo, com checagem sem gabarito.

Texto:

> Monte um estudo curto sobre {foco}, ou sobre o acervo inteiro se foco vier vazio. Use `consultar_acervo` para os pontos. Depois chame `checar_entendimento` sem resposta, faça a pergunta à pessoa e só então chame de novo com a resposta dela. Nunca mostre o gabarito. Se não constar, diga que não consta.

### onde-posso-ler-mais

Argumento `assunto` (texto, opcional). Descrição: referências do acervo e o motivo de cada uma.

Texto:

> Liste referências do acervo sobre {assunto}. Leia só resources em `referencias/`. Para cada uma, diga o motivo em uma frase usando o próprio texto, com arquivo e fonte. Se não houver, diga que não consta. Se assunto vier vazio, liste todas.

## Tools

Leitura e escrita ficam separadas. A única tool que escreve é `registrar_duvida`. Erro é texto que diz o que o modelo faz em seguida. "Não consta" é resultado, não erro.

### consultar_acervo

Descrição: use para responder o que o material diz. Devolve trecho, arquivo e fonte, ou diz que não consta. Não completa com conhecimento de fora.

Schema:

- `pergunta` (texto, obrigatório): uma frase.

Resultado quando acha: lista de trechos, cada um com `arquivo`, `tema`, `fonte`, `autor` e `trecho`. O trecho não inclui o bloco `:::checagem`.

Resultado quando não acha: a frase `não consta no acervo` e a lista dos `tema` carregados, para a pessoa escolher outro. Sem texto inventado.

Erros:

- Pergunta vazia: `Informe a pergunta em uma frase.`
- Pasta sem markdown válido: `Aponte o servidor para uma pasta conteudo/ com markdown (tema, fonte, autor).`

### registrar_duvida

Descrição: use quando a pessoa quiser mandar uma dúvida anônima para a sala. Única tool que grava.

Schema:

- `texto` (texto, obrigatório): a dúvida, sem nome.

Grava só `texto` e horário UTC. Sem nome, sem IP, sem sessão do protocolo. Memória do processo; acaba quando o processo acaba.

Resultado: `Dúvida registrada sem identificação.`

Erros:

- Texto vazio: `Escreva a dúvida em uma frase, sem nome.`

### ver_duvidas_da_sala

Descrição: use só quando quem fala disser que está apresentando. Devolve as dúvidas da sala agrupadas por assunto. Não grava.

Schema: sem argumento.

Agrupamento: se o texto contém um `tema` do acervo, entra nesse tema; senão entra em `geral`. Dentro do grupo, ordem de chegada. Cada item é texto e horário.

Resultado com sala vazia: `A sala ainda não registrou dúvida.`

Erro: nenhum caso de entrada. Não há chave nem identidade neste contrato; token de sala fica para a exposição, fora do P2.

### checar_entendimento

Descrição: use para perguntar e conferir estudo. Na primeira chamada devolve só a pergunta. Na segunda, diga se a resposta fecha com o acervo. O gabarito não volta para o modelo.

Schema:

- `id` (texto, opcional): identificador devolvido na primeira chamada.
- `resposta` (texto, opcional): o que a pessoa respondeu.

Sem `id` e sem `resposta`: escolhe um bloco `:::checagem` ainda não usado nesta memória, guarda a resposta no servidor e devolve `id` e `pergunta`.

Com `id` e `resposta`: devolve `certo` ou `errado`. Se errado, inclui o `arquivo` para reler e não inclui a resposta esperada.

Erros:

- `resposta` sem `id`: `Chame de novo sem resposta para receber uma pergunta.`
- `id` desconhecido: `Essa checagem expirou. Peça outra pergunta.`
- Nenhum bloco `:::checagem` no acervo: `O acervo não tem pergunta de checagem.`

### sobre_este_acervo

Descrição: use para dizer título, autor, versão e a lista do que está carregado, inclusive os atalhos. Não grava.

Schema: sem argumento.

Resultado: `titulo`, `versao`, `autor` e `fonte` de `conteudo/sobre.md`, mais a lista de arquivos com pasta, nome e `tema`, mais os seis nomes de prompt.

Erros:

- Sem `conteudo/sobre.md`, ou sem `titulo` e `versao`: `Falta conteudo/sobre.md com titulo e versao.`

## Resources

Três famílias, uma por pasta. MIME `text/markdown`. O corpo é o markdown sem frontmatter e sem o bloco `:::checagem`.

- `acervo://slides/{arquivo}` — um slide.
- `acervo://manual/{arquivo}` — um passo do manual.
- `acervo://referencias/{arquivo}` — uma referência.

`sobre.md` não é resource; sai só por `sobre_este_acervo`.

Erro quando o URI não existe: `Esse arquivo não está no acervo.`

## O que este contrato não faz

Não escolhe tom final dos prompts. Não cria tool espelhando comando de shell. Não cria uma tool por atalho. Não trata dúvida da sala como sessão do protocolo. Não muda os pacotes do `p0.md`. Não implementa o servidor: isso é o P2.
